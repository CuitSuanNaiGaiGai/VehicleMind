# 在线 Agent Golden Set 评估实施计划

依据已确认的设计文档 `docs/superpowers/specs/2026-09-23-online-agent-golden-set-design.md`。在当前 `codex/agent-eval-design` 分支实施；每完成一个可验收任务即核对 `todolist.md`、测试、提交并汇报，不把候选标签称为人工审定。

## 任务 1：可离线验证的评估框架

1. 为在线客户端增加可配置超时、温度与响应元数据（响应模型、usage）；保持原有调用兼容。
2. 增加 `modules/vehicle_ai/evaluation/`：场景数据契约与严格加载、独立 trial runner、模型请求及工具轨迹记录、确定性 grader、中文 JSON/Markdown 报告。
3. 使用假客户端编写先失败后通过的测试，覆盖工具参数、最终状态、回答事实、失败/待审、隔离运行与无密钥输出。
4. 提供显式 `--provider` 的命令行入口及一条结构化开发集样例；不调用真实 API。
5. 运行全量测试与代码检查，更新任务清单，提交并推送。此处暂停汇报。

## 任务 2：双模型在线预检与 8 条 pilot

1. 补齐 8 条开发集结构化场景及审查记录；保留候选状态。
2. 分别进行 Qwen/GLM 单次真实工具调用预检，记录模型、主机、时间、错误类别。
3. 两模型各跑 8 条一次，逐条核查 trace 与评分，修复兼容问题；失败如实保留。
4. 全量回归，更新清单，提交并汇报。

## 任务 3：40 条金标候选与 80 条变体

1. 完成 24 条开发及 16 条保留结构化样例；用户逐条审定后冻结保留集。
2. 从开发集生成 80 条独立标识的变体，保存来源和抽检记录。
3. 校验数据版本、唯一性、工具 schema、标签及基线测试；提交并汇报。

## 任务 4：正式重复评估与展示

1. 两模型各 40 条 × 3 次；冻结集只在标签审定后运行正式成绩。
2. 输出按模型/分层/类别分解的中文报告，呈现分子分母、稳定性、延迟、请求数、usage 与可追溯失败实例。
3. 保留原始 trial 和运行清单；审查结果、测试、提交并汇报。
