# Agent PendingAction 生命周期设计

## 范围与目标

本轮只处理待确认敏感动作的拒绝、修改目标和超时撤销。ToolRegistry 的强制确认、一次性 action ID 和原始参数执行保持不变。目标是：旧动作一旦被撤销或替换，后续任何确认都不能执行旧目标，并能用确定性测试复核。

## 状态契约

- `PendingActionStore` 仍只保留一个待确认动作。`get()` 自动清除过期动作；过期边界使用 `age >= TTL`，防止到期瞬间仍可确认。
- 增加按 action ID 拒绝的操作：只有当前、未过期且 ID 匹配的动作能被撤销；错误 ID 不清除其他动作。返回结构化结果，便于 CLI、回放和评测记录。
- 目标变更不是“编辑旧动作参数”。用户提出新目标时，先撤销旧动作；搜索/工具返回新规范标识后，创建全新 `PendingAction` 和 action ID。旧 ID 永远不能授权新目标。
- 已清除动作的确认返回 `INVALID_CONFIRMATION`，工具执行历史中不得出现对应成功敏感动作。

## 对话入口

在进入 LLM 前，确定性识别少量明确拒绝语句与改目标前缀（中英文），执行状态撤销；模糊语句不自动视作撤销或确认。拒绝直接返回简短确认，不调用 LLM，也不触发工具。改目标语句清除旧动作后正常进入 Agent 流程，以便通过搜索获得新规范标识。对话入口不直接发行确认凭据；敏感动作仍只走显式 action ID 的 `confirm_pending` 与 ToolRegistry 门禁。

## 组件边界

- `agent/action_state.py`：过期和原子拒绝/替换状态原语。
- `agent/confirmation.py`：面向调用方的拒绝结果与确认控制。
- 新建 `agent/pending_intent.py`：只识别明确的拒绝/改目标表达，不承担完整自然语言理解。
- `agent/vehicle_agent.py`：在构造动态上下文前处理待确认动作的撤销；新目标不能被旧 pending 的 `poi_id` 强制覆盖。
- 回放/测试：覆盖拒绝、错误 ID、到期边界、改目标换 ID、旧 ID 重放失败、LLM 不可信工具调用不能绕过门禁。

## 可验证边界

单元测试与端到端 scripted Agent 测试不依赖在线 LLM、摄像头或模型权重。明确拒绝或改目标后，旧敏感动作执行次数必须为 0。自然语言识别只承诺列明的明确表达，不宣称覆盖所有同义说法；评测需单独报告未识别表达。
