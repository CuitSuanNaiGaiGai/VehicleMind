# Runtime Context Quality Design

The default values in `DriverContext` and `RoadContext` are not evidence of a successful perception result. Runtime quality therefore lives alongside semantic values rather than overloading `False`, `None`, or `UNKNOWN`.

For each domain, `ContextManager` tracks the latest receipt and validity, while each updated field has its own receipt time. A partial update never marks untouched defaults as observed. The field-status order is `MISSING` before that field is updated, `INVALID` after an explicitly invalid domain observation, `STALE` when its last valid receipt exceeds the domain TTL, `UNKNOWN` for a fresh `None`/`UNKNOWN` value, and `KNOWN` otherwise. A fresh `False` is `KNOWN`. Driver and vehicle TTL are 2 seconds; road TTL is 1 second, matching the existing context model's `is_fresh` defaults. Source-frame timestamps are retained as evidence but are not used to compare freshness across domains.

Normal context updates record field receipts and metadata under the same lock as validated semantic replacement. Invalid perception metadata does not mutate semantic fields or publish events; it marks the domain invalid. The new report API returns domain and field quality separately. Terminal demos display missing age as `N/A`. Agent presentation and replay rendering will consume quality in a later increment. Tests use injected monotonic times for deterministic boundary cases.
