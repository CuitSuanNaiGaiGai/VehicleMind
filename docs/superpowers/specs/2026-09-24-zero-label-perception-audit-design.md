# 零人工标注感知核验闭环设计

## 目标与事实边界

基于 `data/perception/cabin/` 与 `data/perception/road/` 中本地视频，建立可重复执行、可追溯、中文可查看的舱内外感知**自动核验**。用户不逐帧画框、不标事件、不绘制掩码。当前目录只有视频，没有与算法输出对齐的人工或官方真值；因此本阶段不计算或宣传 Precision、Recall、F1、mAP、IoU、误报率、漏报率、事件检测延迟或“识别准确率”。已完成的道路性能基准继续保持独立，不把 FPS 当精度。

## 方案与职责边界

选择“两层证据”：第一层对现有视频做资产审计、真实模型推理、运行覆盖与输出分布/时间变化诊断；第二层将来接入任务匹配的官方标签后，再在单独报告中计算有真值的精度指标。本设计只交付第一层及第二层的清晰接口约束，不下载大数据集、不从文件名、视频时长或模型输出推断真值，不引入第二个模型作所谓金标。若数据来源、许可暂未确认，清单保留 `unknown`，公开报告只给聚合数字和限制，不公开视频、画面或身份信息。

## 输入、取样与来源

- 输入为显式指定的两个本地目录，分别最多纳入 50 个视频文件；按相对文件名排序并冻结文件列表，不因运行过程中新添文件而改变分母。拒绝多于 50 个文件而不是静默截断。只接受可解码视频；对无法打开、空视频、无有效帧记录逐项失败，不从尝试数中剔除。
- 每个文件记录相对 ID、basename、字节数、SHA-256、分辨率、FPS、帧数、时长和来源状态。来源状态默认 `unknown`，可由用户提供的独立来源清单补充；不得仅凭数字文件名推断 Nexar 类别或凭 `P104...` 推断 NITYMED 的事件标签。SHA-256 用于去重和复核；同一视频裁成多段时仍不能宣称独立驾驶员或道路场景。
- 正式运行处理整段视频，并使用视频时间戳驱动舱内时序状态；不能跳帧后仍沿用原 PERCLOS、哈欠或眨眼阈值。可选小规模 smoke 模式仅验证管线，不进入公开聚合数字。舱外沿用现有工作尺寸、模型与 provider 设置；记录实际 session provider，CoreML 失败时不记作 CoreML 成绩。

## 运行器与本地结果

- 一个轻量编排入口枚举与校验资产；舱内、舱外各有独立适配器，分别调用现有 `CabinPerceptionService` 和 `DrivingPerceptionService`，避免把两套业务逻辑塞进大文件。每个视频独立初始化有状态的服务，禁止上一个视频的 PERCLOS、存在状态或事件计数泄漏到下一个视频。
- `runs/perception_audit/<run-id>/` 中写入 `manifest.json`、逐视频结构化结果、`summary.json` 和中文 `report.html`/`report.md`。逐视频数据包含视频时间戳、抽样展示点的输出以及必要的状态转移记录；完整原始帧不落盘。文件级异常写入失败记录后继续剩余视频；模型或配置整体不可用则立即失败，并保留清晰原因。
- 运行记录包含 Git commit/dirty、配置快照、模型哈希、依赖版本、平台、开始时间与随机 run ID。公开报告不含本机绝对路径、密钥、视频画面、个人轨迹或完整模型请求。旧运行只读，不覆盖；只在全部规定产物写完后标记完成。

## 可以量化的内容

| 主张 | 指标与分母 | 不能解释为 |
|---|---|---|
| 视频可处理性 | 成功处理视频数 / 尝试视频数；按舱内/舱外分别报告，并列失败原因 | 感知正确率 |
| 输入与执行覆盖 | 实际处理帧数、有效输出帧数、来源/许可状态、模型与 provider 配置 | 独立样本数量或场景覆盖率 |
| 舱内输出行为 | 逐视频 face-visible、eye-closed、yawn、driver-state 的出现次数/持续时间与状态转移；报告未知或不可判输出 | 疲劳/哈欠检测 Precision、Recall 或误报率 |
| 舱外输出行为 | 逐视频目标类别/计数、lane/drivable 输出比例与相邻帧状态变化；记录无输出与异常 | 检测 mAP、车道/可行驶区 IoU 或稳定性等于准确性 |
| 性能 | 可选记录当前任务的处理耗时，但不与已有无绘制/编码道路基准混用 | 上车实时能力 |

报告中的百分比必须同时列分子、分母和单位；视频级与帧级分母分开。相邻帧变化仅称“输出波动”，不因缺少人工真值而命名为误报或漏报。典型案例仅在本地 HTML 中以可点击时间戳关联原视频，不自动把含人脸/车牌的画面上传 GitHub。

## 后续官方标签入口

只有当官方标签能明确映射至同一原始视频或帧、时间戳、类别和空间坐标，并记录版本、划分与许可，才建立单独的 `reference_labels` 输入。舱内视频级类别不能自动当作逐帧疲劳真值；Nexar 碰撞/险情标签不能充当车辆框、车道或可行驶区真值。若使用 YOLOPv2 训练所涉及的 BDD100K，必须核对模型来源和数据划分，不能把可能重叠的训练画面包装成独立泛化结果。没有这些前提时精度字段必须为 `not_evaluated`，不得填 0 或伪标签成绩。

## 验收

1. 无摄像头、无 API Key、无人工标注，可对本地两目录运行；CI 通过伪视频/伪服务覆盖枚举、去重、失败分母、状态隔离、路径脱敏和指标命名，不依赖真实权重。
2. 本机烟测验证真实权重和视频可用；正式运行前检查感知依赖是否完整。若缺 MediaPipe/ONNX Runtime，给出安装与复跑说明，不把失败运行写成测量结论。
3. 中文报告能让用户直接看到 26 段舱内与当前舱外目录的**实际**尝试数、成功数、每视频状态/目标输出和异常；视频数按运行时冻结清单呈现，不把多个帧当多个独立视频。
4. `README.md` 和 `todolist.md` 只更新真正完成的自动核验项；舱内外精度、人工标注和官方标签对照仍保持未完成。任何公开数字附运行条件和局限。
