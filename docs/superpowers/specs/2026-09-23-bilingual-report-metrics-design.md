# 回放报告技术指标双语展示设计

## 目标与现状

用户已确认：`report.html` 中的技术指标采用“英文（中文含义）”标签，非指标说明继续使用中文。当前 `runs/drowsy-rest-stop/report.html` 是改动前生成的英文历史产物；模板已更新但生成器不会覆盖已有结果目录，因此仅修改模板不能改变用户正在打开的文件。

## 展示规则

- 顶部指标、统一上下文字段、观测质量字段、时间线中的技术字段以及断言中的技术名称统一显示为 `English（中文含义）`，例如 `Runtime（运行耗时）`、`risk（风险等级）`、`confidence（置信度）`、`unauthorized_sensitive_executions（未经确认的敏感动作执行次数）`。事件类型与工具名若出现在时间线或断言中，也使用 `HIGH_RISK_DETECTED（检测到高风险）`、`start_navigation（启动导航）` 这类形式。
- 保留协议中的精确英文键、事件类型与工具名，以便读者从可见标签追溯到 `summary.json` 和 `trace.json`；中文释义放在全角括号内。对未建立释义的字段，显示 `raw_key（未翻译字段）`，不静默猜测。
- 页面标题、面板标题、状态、场景叙述、失败说明与证据限制继续使用中文。数值中的状态枚举可以显示中文释义，但应保留需要定位的原始枚举，例如 `STALE（已过期）`；文件路径、哈希和 ID 原样显示。
- 报告数据协议不变。双语映射只在 `report.js` 的展示层实现，不增改机器可读 JSON 字段。

## 旧报告与新报告

- 不覆盖或删除现有 `runs/drowsy-rest-stop/`：它是此前运行的历史证据，必须明确告知用户其页面仍为英文。
- 使用新的运行标识（例如 `drowsy-rest-stop-bilingual`）生成报告，给用户提供该报告的绝对路径和打开命令；README 补充“旧报告不会自动更新”的说明。
- 不把重新生成报告描述为重新执行感知模型。该场景仍使用录制的语义观测。

## 验证

1. 报告 JS 的渲染测试检查顶部、上下文、时间线、断言中的双语标签，以及未知字段、`STALE`/`INVALID` 与失败断言的显示。
2. 回放集成测试确认 `summary.json`、`trace.json` 的键、工具名和语义断言保持原样。
3. 使用新运行标识实际生成报告，检查新页面与 JS；旧结果目录保持不变。
4. 运行完整 pytest、Ruff、格式、类型与文件长度检查；通过 PR 合并并同步本地 `main`。
