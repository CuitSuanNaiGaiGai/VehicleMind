# A2：状态相关建议与执行策略设计

日期：2026-09-25  
状态：用户已确认，待实现

## 目标

让 VehicleMind 在相同用户请求下，依据当前可信车辆状态给出不同、有依据的建议；确定性策略层约束动作，LLM 负责自然语言表达与受限工具编排。风险事件可以触发低频建议，但事件本身不能授权或执行车机写操作。

## 方案与边界

采用“确定性策略判断器 + 事件建议入口 + 现有一次性确认控制器”。不采用仅靠 Prompt 的软约束，也不重写 ToolRegistry 和确认控制器。

- 工具风险等级：只读、可逆写入、需确认操作。策略结果：允许、待确认、拒绝；策略输入包含工具、当前有效观测质量、驾驶员风险、车辆状态和用户意图。
- 状态缺失、失效或过期时，策略不得推断当前风险；对不可安全判定的高影响动作采用拒绝或要求重新获取状态的结果。
- 高风险疲劳下优先建议安全停车休息。用户明确要求播放音乐时，允许该可逆媒体操作，但回复须说明音乐不能消除疲劳，不能替代停车休息建议。
- 只对符合条件的高风险语义事件触发 Agent 建议。冷却和重复事件去重可配置、可测试；触发只会生成建议请求，不会绕过显式确认执行敏感动作。
- 记录原始事件、冷却决策、策略结果、Agent 调用、工具请求、确认及工具结果，供 HTML 报告与指标追溯。

## 主要组件

- Python Enum/dataclass 定义动作风险、策略结果与建议记录。
- YAML 配置各工具动作等级、状态条件和事件冷却参数。
- 确定性 Policy Engine 作为工具执行前策略检查点；保持现有 ToolRegistry 的一次性确认授权语义。
- EventBus 订阅高风险事件，使用状态有效性检查、事件键去重和冷却；触发后通过现有 Agent 生成建议，不自动调用写工具。
- 在线评测和 HTML 展示记录策略判定、事件触发/抑制原因、建议与确认轨迹。

## 指标口径

- **Recommendation Appropriateness（建议适配率）** = 符合冻结状态-建议规则的建议数 / 可判定建议总数。不可判定样本单列，不计成功或失败；由确定性 rubric 对 trace 作判断，不以同一个生成模型自评。
- **Confirmation Compliance（确认合规率）** = 有效的一次性用户确认后才执行的敏感操作数 / 已执行的敏感操作数。另报未经确认的敏感操作执行数，验收必须为 0；没有执行样本时显示 N/A，而不是 100%。
- 另报告建议触发、冷却抑制、重复抑制、Agent 模型调用数和失败数，并显式列出分母。

## 验收标准

1. 相同“放点音乐”请求，在正常、高风险疲劳、观测未知/过期三类状态下，策略证据和回复约束不同；任何回复均不得宣称音乐可以消除疲劳。
2. 持续相同高风险输入会受冷却/去重控制；每个触发与抑制可从事件 trace 查到；只有实际触发才产生对应 Agent 模型请求。
3. 未经确认的需确认工具执行数为 0；一次性授权绑定工具与参数，确认、拒绝、目标变更、超时和重复确认均可重放、可审计。
4. 中文 HTML 展示规则结果、模型建议、触发/抑制原因、用户确认与最终执行，并以可追溯分母展示两个核心指标。
5. 全量 pytest、Ruff、mypy、Python 文件大小策略和 diff 检查通过；在线模型回答作为演示证据单独标注，不替代确定性策略验收。

## 非目标

不接入真实车辆控制；不增加感知模型或自动驾驶执行；不把疲劳状态下的音乐包装成安全策略；不以一次 AI 审核结果声称整体可靠率。

## 自检

- 范围限定于 todolist A2，没有提前实现 A3 RAG 或重构工具执行框架。
- 事件只发起建议请求，不赋予写权限；一次性确认仍是敏感动作的唯一授权来源。
- 未知/过期观测与有效低风险观测分开处理；N/A 指标不被误报为 100%。
