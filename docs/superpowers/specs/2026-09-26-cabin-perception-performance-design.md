# 舱内感知处理性能基准设计

## 目标

让现有无标签视频自动核验同时产出可复现的舱内处理性能证据，回答模型初始化、首帧开销、稳态单帧延迟与离线回放吞吐；不增加任何感知准确率或事件正确性结论。

## 当前问题

`CabinPerceptionService.process_frame()` 已通过 `CabinPerceptionSnapshot.metadata.processing_ms` 暴露单帧处理时间，但 `modules/perception_audit.process_video()` 没有保存该值。现有 26 条舱内视频共处理 30,063 帧，已有结果只保留输出行为和处理覆盖，无法从现有 `runs/` 结果恢复历史处理延迟。

## 方案选择

采用扩展现有自动核验流水线的方式。单独增加舱内 benchmark 会重复视频解码和服务构造逻辑；一次性计时脚本则不能形成可回归、可复跑的仓库接口。

## 采集口径

- 每条舱内视频记录独立服务初始化耗时 `service_init_ms`。
- 每个处理帧读取 `snapshot.metadata.processing_ms`。每条视频首帧独立作为 `first_frame_ms`；其余帧作为稳态样本，避免把首帧开销混入稳态 P50/P95。
- 记录视频读取与逐帧处理循环的墙钟耗时 `replay_loop_ms`。离线回放吞吐为成功视频的处理帧总数除以循环墙钟时间总和。
- 性能汇总只使用完整成功处理的视频；分位数同时提供样本数、均值、P50、P95、最小与最大值。没有可计算样本时用 `null`，不伪造 0 延迟。
- `processing_ms` 是服务单帧调用耗时，不包含视频解码和页面展示；`replay_loop_ms` 包含视频读取、逐帧服务调用和结构化结果更新，不包含服务初始化与报告渲染。吞吐不能解读为实时摄像头帧率或端到端车机延迟。

## 结构与隐私

- 新增小型 `modules/perception_audit/performance.py`，只负责有限值校验与毫秒样本统计。
- `process_video()` 只在舱内结果中记录性能样本；原始时延样本留在本地被 Git 忽略的运行 JSON，公开 Markdown/HTML 只出现聚合值。
- 现有 `manifest.json` 继续提供平台、Python、依赖、模型哈希和有效配置快照；不增加视频路径、画面、检测框或个人信息。
- 旧版运行 JSON 缺少性能字段时仍可汇总和渲染。

## 展示与验收

- 中文报告新增独立“舱内处理性能”区域，指标名采用 `English (中文含义)`，至少展示视频数、处理帧数、初始化 P50/P95、首帧 P50/P95、稳态单帧 P50/P95 与离线回放 FPS。
- HTML 继续只展示聚合性能，不把每帧时延展开到页面；逐视频展示可见各视频状态，不泄漏本机绝对路径。
- 用伪服务测试计时字段、失败/空样本与旧报告兼容；在本机舱内/舱外 26 条固定视频和对应模型上重跑完整审计，记录生成版本、配置与模型哈希。
- 精度状态继续为 `not_evaluated`；不进行消融实验，不新增人工标签。
