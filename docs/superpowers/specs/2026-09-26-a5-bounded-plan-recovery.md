# A5 受限计划与失败恢复设计

状态：依据既有路线图直接实施。范围是可回放、可核验的模拟服务区导航任务，不代表真实地图或车辆控制能力。

## 问题与目标

当前 Agent 已有单轮/工具次数/时间预算、一次性确认门和未知写入结果核对，但服务区搜索只返回固定首选地点，也没有面向用户可见的任务步骤和“失败后提供替代地点”的流程。目标是在不更换 Agent 框架的情况下，为休息地点任务增加有界计划、可注入故障、可解释恢复和可复现报告。

## 方案取舍

1. 引入通用多 Agent/工作流框架：能力扩展空间大，但会重复实现当前工具循环与确认门，并增加依赖和排错面；不采用。
2. 仅扩写 Prompt 并开放模型自由重试：改动少，但无法约束重复写操作、候选地点来源和预算；不采用。
3. 在现有单 Agent 外围增加专用有限状态计划器：复用 `AgentTask`、`TurnBudget`、`ToolRegistry`、PendingAction 与 SQLite 轨迹；本项目采用此方案。

## 计划契约

休息导航只允许以下可观察步骤：

`UNDERSTAND → SEARCH → SELECT → AWAIT_CONFIRMATION → EXECUTE → VERIFY`

按需知识查询作为可选 `KNOWLEDGE` 步骤；没有知识服务时显式跳过，不阻止地点搜索。终态为 `COMPLETED`、`FAILED`、`CANCELLED` 或 `STOPPED_NO_RESULT`。每个步骤记录状态、开始/结束时间、成功条件、证据摘要、失败码和剩余预算。最长分支允许 9 个实际步骤（含替代地点的二次确认和执行），最大 1 次恢复；上限由 YAML 配置并在运行产物中固化。

地点工具返回有稳定 `poi_id` 的结构化候选列表，按距离和用户给定的偏好过滤/排序。无候选时返回 `NO_RESULTS` 并明确停止。地点 ID 只接受当前计划搜索结果里的规范 ID。候选的模拟可用性由本地目录决定，页面明确标出“模拟数据”。

若主候选在已确认后返回可恢复的 `POI_UNAVAILABLE`，计划最多选择一个不同候选，并建立新的 PendingAction；替代地点需用户再次确认，之前的确认不继承。若没有候选、错误不可恢复、用户取消/改目标或预算耗尽，计划进入终态，不再产生写调用。未知写入结果沿用只读状态核对并停止，禁止重放。

## 可观测性与评测

每次计划步骤写入 Agent trace；启用 A4 存储时作为 `TASK_STEP` 事件持久化。确定性场景覆盖成功、主地点不可用后替代、无可行地点、用户取消、非法/非候选 POI、只读查询失败、预算耗尽及未知写入。报告统计：

- `Recovery Success（恢复成功率）` = 可恢复注入场景中满足终态成功条件的场景数 / 可恢复注入场景数。
- `Safe Stop（合理停止）` = 无候选/不可恢复场景按预期停止的次数 / 此类场景总数。
- `Duplicate Write（重复写操作）` = 相同任务对同一目的地的未授权或自动重放写调用数，目标为 0。
- `Budget Compliance（预算合规率）` = 未超计划步数/恢复次数上限的 trial 数 / 总 trial 数。

试验数是有限的脚本化故障场景，不称独立人工金标。每个指标保存分子、分母、场景 ID、配置哈希和原始 trace。

## 安全与范围边界

- 计划器只编排当前模拟工具，不连接 CAN、真实导航服务或车辆控制接口。
- LLM 可提出步骤意图，但确定性计划器校验候选 ID、预算、当前状态和确认授权。
- PendingAction 绑定规范工具名及参数；替代地点产生新的 action ID 与新确认。
- 禁止在失败后自动切换目标并执行，禁止对未知结果重放写操作。
- UI 把“感知/上下文事实”“模型建议”“模拟地点/车机结果”分开展示，不暴露隐藏思维链。

## 验收标准

1. 成功、首选不可用后转呈替代地点、无可行结果停止三类场景可离线复现。
2. 所有步骤带时间、证据/错误、预算；取消后没有新增敏感写调用。
3. 替代地点需新确认，非搜索候选 ID 被拒绝；写操作结果未知不自动重放。
4. 计划和恢复报告中文可读，展示真实模拟步骤，指标有分子分母与边界声明。
5. 相关测试在无 API Key、摄像头和在线服务环境通过，模块遵守 500 行上限。
