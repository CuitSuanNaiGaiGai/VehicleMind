# Offline Video Pipeline Design

The integrated perception demo will use local cabin and road videos instead of a camera. The selected local defaults are `assets/demo/MicroSleep_test.mp4` and `assets/driving/road_test.mp4`; neither is committed, so callers may override paths and a fresh clone still uses the existing scenario replay for zero-asset operation. Real perception remains optional and must be labeled separately from recorded semantic replay.

Each source runs four independently scheduled stages: video decoding, model inference, context/event update, and terminal status display. Three bounded channels connect them. The frame channel drops the oldest unprocessed frame when full; the semantic snapshot channel blocks its producer, preserving every completed inference result while backpressure reaches the frame channel; the display channel drops old status cards. Queue capacities and rates are explicit CLI parameters. Cabin, road, and user-triggered Agent work run independently. A looping video source provides strictly increasing frame timestamps across loops, which the cabin MediaPipe path requires.

Each stage reports heartbeat, last error, queue depth, dropped items, processed count, and latency observations. The pipeline never creates an unbounded backlog, and stopping closes channels and releases video/model resources. Core queue and pipeline tests use fake sources and inference callbacks; a local video decode smoke test can use ignored videos without requiring a camera. `todolist.md` should only mark a task complete after integration and tests, not merely because the queue class exists.
