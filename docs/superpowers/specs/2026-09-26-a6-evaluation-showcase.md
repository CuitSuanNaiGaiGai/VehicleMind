# A6 贯穿式评测与招聘展示设计

状态：依据现有 TODO 直接实施。目标是把已完成的 A1–A5 能力整理成可复现、可核对的招聘展示入口，并验证 A5 改动没有破坏旧 Agent 评测链路；不是再增加一个新 Agent 框架。

## 已有条件与需要补齐之处

- 仓库已有 40 条 SHA-256 冻结的 AI 自审 Agent 内部场景、双模型 × 每场景 3 次的历史运行与逐条审核记录；这不是人工金标准，也不能当作未见测试集。
- 在线展示 HTML 已含舱内外 GIF、关键观测、模型实际上下文、工具执行和折叠原始数据；本次只把 A5 计划步骤及恢复信息接入该视图，不重做已有媒体面板。
- A5 新增 7 个确定性恢复场景及独立中文结果页。此套件和 40 条在线 LLM 语义评测具有不同实验对象与分母，必须分开报告，不能合成单一成功率。
- 感知视频暂无独立真值标签；沿用零标注处理覆盖证据，不计算 Precision/Recall/F1，不把无标签自动输出写成准确率。

## 方案与验收

1. 扩展 `task_display.py`，从记录的 `TaskPlan` 快照展示步骤、候选地点、预算、状态和失败/恢复证据；每项均来源于 trace，不臆测缺失字段。原始请求/JSON 仍折叠，GIF继续在 HTML 内引用。
2. 用现有冻结 loader 和 batch runner 核验 40 个历史场景及哈希；若重跑，模型/场景/提交与次数写入原始 run。在线试验每模型、每场景重复 3 次；在线评分仍标记待语义审核，AI 审核不叫独立人工评测。
3. 为受 A5 改动影响的 `SHOWCASE01` 使用 Qwen、GLM 各运行 3 次，报告模型调用、工具参数、确认与终态；不把候选展示场景混进 40 条冻结场景分母。
4. 在 README 和面试讲述卡形成入口矩阵：离线完整 Demo、A5 故障验收、Qwen/GLM 在线评测、感知零标注核验；每个数字链接到报告并标注口径、分母、局限。
5. 对 TODO 旧项逐条以代码/测试/报告核对：已有证据则勾选并引用；无真值标签、未确认数据授权或硬件条件的目标明确后置，不能为“清空清单”伪造结论。

## 不在本任务范围

- 不制作演示视频（此前已明确暂缓）。
- 不手工标注舱内外数据，不宣称感知准确率。
- 不连接真实车机，不把模拟导航表述为真实导航。
- 不把模型重复 trial 当作独立场景或新增金标准。
