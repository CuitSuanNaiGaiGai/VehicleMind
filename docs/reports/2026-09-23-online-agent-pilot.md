# 在线 Agent 双模型候选 pilot 技术报告

## 范围与可复现性

本报告是 8 条**开发集候选**场景的单次 pilot，不是 40 条人工审定 Golden Set 的正式成绩，也不计算任务成功率。两模型均从干净提交 `9125b1d09755143e047e469f149797fce5ec71d9` 运行，`git_dirty=false`。Qwen 使用 `qwen3.8-max` / OpenAI 客户端 `2.54.0`；GLM 使用 `glm-5.1` / 智谱客户端 `2.1.5.20250825`。请求温度 0.2、超时 30 秒、客户端重试 0 次、最多 5 轮工具调用。场景、工具和车辆状态均为本地合成数据；没有真实车辆控制。

本地完整证据：

- Qwen：`runs/agent_eval/pilot-20260923T131549010372Z-qwen/pilot.json` 及同目录每条 `trial.json`
- GLM：`runs/agent_eval/pilot-20260923T131605231383Z-glm/pilot.json` 及同目录每条 `trial.json`

`runs/` 按仓库规则不提交 GitHub。上述路径供当前工作区复核；重新执行命令会生成新的独立目录，结果可能因在线模型非确定性而变化。

## 运行结果

两家 API 均通过真实工具调用预检，且各完成 8/8 条候选 trial；运行异常均为 0。预检每家各发起 2 次模型请求。8 条 trial 内 Qwen 共 14 次请求，API 返回输入 22,009、输出 372 token；GLM 共 15 次请求，输入 19,447、输出 1,520 token。token 是客户端返回值汇总，不是账单或费用估算。

| 场景 | Qwen 机械判定 | GLM 机械判定 | 技术审查要点 |
|---|---|---|---|
| C01 疲劳 | 待审 | 待审 | 均报告疲劳与高风险；中文语义仍需人工判定。 |
| R02 车道未检出 | 待审 | 待审 | GLM 把未检出归因于驻车，输入未提供这一因果关系。 |
| X01 联合休息建议 | 待审 | 待审 | 均未调用工具；GLM 提到未在场景中给定的 PERCLOS 阈值。 |
| X03 分心自述＋道路 | 待审 | 待审 | 当前舱内契约无分心标签；GLM 推断车道偏离预警能力，需核查。 |
| T02 查询空调 | 待审 | 待审 | 均调用 `get_climate_status`，回答与工具返回值一致。 |
| T03 调温 22→24°C | 待审 | 待审 | 均调用 `set_temperature`，最终目标温度 24°C。 |
| T05 播放《晴天》 | 待审 | 待审 | 均调用 `play_music`，媒体状态与标题达到候选期望。 |
| M01 搜索后确认导航 | 待审 | 失败 | Qwen 在确认前把待确认表述为“启动失败”；GLM 重复请求需确认工具，机械工具序列不匹配。两者最终经显式确认后才进入 ACTIVE，不能凭最终状态宣称端到端成功。 |

机械判定中的“待审”只表示当前工具、参数、最终状态与简单禁语检查没有发现问题；回答依据与交互时序仍需独立人工审定。当前候选场景的 `required_facts` 均未冻结，不能将“待审”换算成通过数。

## 已发现问题与下一步

1. Agent 将 `CONFIRMATION_REQUIRED` 当成普通失败交给模型继续推理，导致重复工具调用或误导性失败回复。下一节点先改成明确的待确认状态输出，并为多轮确认增加回归测试。
2. 语义判定目前只做有限关键词检查；应在人工审定的必要事实、禁止推断及回复时序上完善标签与 grader，避免幻觉陈述进入“待审即成功”的误读。
3. C01/R02 等场景仍有初始车辆状态默认值；下一阶段制作 40 条候选金标时需逐条审查初始状态、允许的工具变体与事实边界，用户审定后再冻结保留集。

前两轮探索性运行发现了 X01、T02 的措辞歧义，以及 T03 初始目标温度默认就是 24°C 的标注错误；这些旧运行不纳入上表。修订过程和待审点见 [`scenarios/agent_eval/candidates/REVIEW.md`](../../scenarios/agent_eval/candidates/REVIEW.md)。
