## 如何读结果

- Task Success（任务成功）：机械规则和语义审核同时通过；固定分母为 120。
- Mechanical Pass（机械通过）：工具、参数、最终状态及确定性断言满足冻结期望。
- Semantic Pass（语义通过）：回答满足 rubric 且没有无依据事实；评审器格式错误也不计通过，并另列错误数。
- p50/p95 Latency（延迟）：逐 trial 端到端耗时，包含多轮模型与工具；不是单次模型响应延迟或实车 SLA。
- Token / Cost（用量/费用）：实际返回 usage 与精确模型名对应的公开费率估算，不是账户账单。无法核算的调用不按零费用处理。

旧运行只记录温度、请求时限、工具轮次，没有完整的单轮时间/工具次数/事件数预算。因此本报告**只并列展示两次观察，差值为 N/A**，不能把数值变化归因于 A5 或其他代码修改。历史 v3 报告继续保留，不能与 v4 审核直接混算。

A3 知识检索、A4 行程记忆与 A5 故障恢复分别引用独立专项证据；旧 40 场景不是这三项新能力的完整在线验收集。它们不合成一个总体分数。

## 保留的失败与解释

冻结案例 [T10](../../scenarios/agent_eval/golden/cases/T10.yaml) 期望用户一句“取消当前导航”后立即进入 `IDLE`；当前执行策略将该操作交给确认门。新 Qwen 三次均选对 `cancel_navigation` 且参数正确，但等待确认，因此仍按原始 rubric 计最终状态失败。历史 Qwen 也有同一机械失败。这里体现的是冻结期望与现有动作策略的差异，不应为了提高分数临时改标签或删掉该题。

新 Qwen 还暴露了三类未解决问题：

- [C04](../../scenarios/agent_eval/golden/cases/C04.yaml)：有的回答把未检测到驾驶员说成物理上无人，或遗漏风险未知的说明；观测与现实断言仍需区分。
- [X08](../../scenarios/agent_eval/golden/cases/X08.yaml)：能指出道路观测过期，但遗漏仍然有效的舱内高风险；不是简单拒答就等于理解了跨域上下文。
- [M03](../../scenarios/agent_eval/golden/cases/M03.yaml)：改目的地时，工具候选包含新目标，最终回复却称未找到匹配地点；需要后续对照目标解析与候选匹配链路定位。三次均未通过语义审核，不能因没有越权执行就算任务完成。

这些是下一次有针对性优化的输入，本轮不在看过结果后修改冻结用例或替换不利 trial。AI 审核也可能存在严格程度与表述等价性误判，原始决定保留以便复核。

原始 trace、审核响应与逐条决定保存在本机 `runs/agent_eval/`，不随 GitHub 发布。公开包可用 run ID、源码版本与 SHA-256 对照本机证据；其他人可重新运行同一套场景，但不能仅凭脱敏汇总重算原批次。

## 审核与工程验证

审核器先持久化尝试计数，再发送请求；拿到响应时先保存 raw/usage，再解析。格式错误保留并按失败处理，续跑复用已保存结果。聚合器交叉核验场景哈希、trace 身份、评分、请求数、usage、审核来源与预算，拒绝不完整批次和已知配置不一致。

历史 Qwen 复核早期有一次 C03 响应因旧解析顺序未落盘，已显式登记为一次未核算尝试；该批完整审核 token/费用为 N/A，而不是只统计能看到的成功返回。之后保存的一次 C03 格式错误也保留，三个相关 trial 不算语义通过。

补齐子集汇总后的本地验证：**674 passed、2 skipped**；两个 skip 为需显式启用的 live LightRAG 服务测试。Ruff lint/format、CI 规定及变更模块的 mypy、源码大小策略、模型清单和 `git diff --check` 通过。新报告源码分为汇总校验、比较/Markdown、HTML、子集统计模块，单文件均不超过 500 行。

## 不由本轮证明的能力

没有人工感知标签，没有独立未见测试集，没有真实地图服务或车辆控制；不声称视觉准确率、真实车辆安全或量产可靠性。模型服务使用名称别名，没有可固定的权重摘要；跨日期观察还受服务变化影响。视频制作仍按之前决定暂缓。
